Verdict

A harness for checking predictive claims, and the record of what happened when claims were put through it. 4 adjudicated so far.

Predictive claims are cheap to make and expensive to check. Checking one properly means the same unglamorous discipline every time: build the data as it stood at the time, split only by time, seal a block and open it once, compare against what you already had, price the frictions, perturb the definitions, and — when the answer is no — find out which mechanism said no. This is that discipline written as code, plus the verdicts it produced.

How a claim is audited

a claim arrives (a paper, a pitch, an idea)
  ↓
1. extract — signal, universe, frequency, claimed effect, sample, data needed
  ↓
2. pre-register — splits, benchmarks, costs, diagnostics, and what result would kill it
  ↓
3. a person approves the protocol — before any data is touched
  ↓
4. execute — deterministic code computes every number
  ↓
5. diagnose — if the answer is no, find the mechanism
  ↓
6. record — a verdict with mandatory limitations, and a card in this register

Step 2 is the one that matters. Writing down what would falsify a claim before seeing the data is what stops the answer from being retrofitted to the result, and it is the step that gets skipped.

Why the numbers can be checked

guaranteehow it is enforced
A sealed block opens once Every opening is written to a ledger with its reason and a fingerprint of the analysis configuration. Re-opening under a changed configuration raises.
Negative results are publishable The document renderer refuses to produce a verdict whose honest-limitations section is empty.
Prose does not invent figures Every number in a written verdict is checked against the values the analysis returned; anything unsupported is flagged and the draft is withheld.
The harness can find a real effect Known-answer controls plant an effect that only a flexible model can see, and require the harness to detect it. A null from a harness that can only find nulls is worth nothing.
Audits do not vouch for themselves The leakage and membership checks re-derive timestamps independently and never import the code they are checking.

Reading a verdict

Each case page carries the full write-up: what was audited, what was found, the figures, and an honest-limitations section that says what the run cannot settle. Every case is reproducible offline from pinned data with the commands in its own README, and the numbers in the write-up are interpolated from the results file rather than typed in.
